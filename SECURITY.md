# Security policy

## Supported versions

Before the first public release, security fixes are made on the current default
branch. After publication, the newest `0.x` minor line will receive security
fixes. Older `0.x` releases may require an upgrade because breaking changes are
still possible before version 1.0.

## Reporting a vulnerability

This repository does not yet declare a private security contact. Before the
first public release, the maintainers must configure private vulnerability
reporting with the repository host and update this file with the exact route.

Do not post exploit details, secrets, or a working proof of concept in a public
issue. If private reporting is not available, share only a request for private
contact through the normal project channel.

A useful report states the affected version, environment, impact, and the
smallest reproduction that demonstrates the problem. Remove credentials and
personal data from logs and examples.
